## 1. 同一语义段，一个文本对象

### 1.1 默认制作单位

同一框中连续表达同一内容的几行文字，用一个多行文本对象排版。换行是该对象内的排版行为，不是新建一个对象的理由。

例如 `Inspect History\nAdapt Surrogate`、`Critical Paths / Slack\nFanout / Connectivity`、`Best Verified State\nODB + SPEF` 分别是一个多行内容单元。不能把其中每个显示行单独定位，否则行距、宽度、对齐和后续编辑会分别漂移。

一个文字块包含标题和说明时，优先使用同一文本对象中的段落或富文本样式：标题可粗体或有色，说明统一正文字号；标题之后的间隔是段距，同一说明里的换行采用行距。不要把每行做成不同字号的独立对象来凑层级。

### 1.2 允许分开的对象

模块标题位于独立顶栏，正文位于另一内容区；表格内不同单元格；需要独立锚点的路径标签；图上的不同实体标签，均可各自独立。一个 Agent 外框内部本来就可能有多个步骤，不要求把所有步骤的文字合成一个对象。

同一内容框中的小标题和说明，如工具确实无法处理所需富文本，可以保留两个语义对象，但要统一以父容器和实测文本高度计算位置，不逐行拆分。对用户已经明确要求一个文本框的段落，制作方式应满足这一要求，不能仅把多个框编组后声称已经合并。

### 1.3 常用格式的落实方式

| 格式/工具 | 正确的文字单位 |
| --- | --- |
| PPTX | 一个文本框或形状的 text body；用软换行、明确段落和 runs 区分样式，检查段前段后默认值 |
| Draw.io | 一个内容节点/cell 内的多行文本或富文本，不为每个显示行新建节点 |
| SVG | 一个语义文字块用 `<text>` 配合 `<tspan>`，共享锚点与统一的行进距离；不逐行任意坐标定位 |
| Matplotlib | 同一正文段用一次多行 Text 调用及统一 linespacing；确需分开的标题按段距与文本边界定位 |

PDF 导出可能把一个源段拆成多个文本 span，不能由 PDF span 数量或 PNG 截图直接断定源图是否逐行建框。需要核对真实可编辑源文件。

## 2. 字距、行距、段距与内边距

必须区分以下变量，不能把它们统称为“间距”：

| 变量 | 控制什么 | 规则 |
| --- | --- | --- |
| 字符间距 tracking | 字符之间额外的距离 | 默认使用字体自然间距，同类一致；不为塞框任意拉宽、压窄 |
| 字偶距 kerning / 词间距 | 字形组合和单词间的阅读节奏 | 保持正常排版，不手加空格填满行，不用分散对齐制造大洞 |
| 行距 | 同一段内相邻行的基线距离 | 同级同类内容统一，不能按每行手摆位置 |
| 段距 | 标题与说明、不同段落之间的距离 | 明确设置，不能继承不明的默认段前段后值 |
| 内边距 | 字块与所属框边之间的距离 | 同类容器统一，防止文字贴边；去除无用默认值不等于一律设零 |
| 对象间距 | 步骤之间、模块之间、背景范围之间的距离 | 按归属和连线路径分层控制，不要求全图所有空隙等大 |

行距以所用工具的实际度量为准，不把 Matplotlib 的倍率原样当成 PowerPoint 的单位。可先在最终字号下试约 1.1–1.2 的行距，再看 Times New Roman 的字形、上下标及框高；这是排版起点，不是验收硬阈值。两行短标签和长解释段可以采用不同的语义样式，但同类保持一致。

单词换行用正常行距；独立条目若需要段落，明确设置段距。不把每一显示行都创建成带默认段后空白的新段，制造假行距。

## 3. 字体、字号与大小写

本系列默认 Times New Roman，既设置默认样式，也核查局部富文本、粘贴文字、粗斜体与公式是否继承正确。使用自然字符宽度，不对文字做非等比例缩放，不因框窄换成窄体来伪装同一字体。

同一语义等级采用同一字号/粗细规则。标题、正文、注释可以分级；不能因每个框内容多少不同而随机缩字。整图放入论文后的缩放比例不同，会改变最终字号，跨图比较以相同物理尺度为准。

短标签采用统一 Title Case；说明句可采用 Sentence case。两者分别属于不同文字角色，不要求整张图每个单词首字母都大写。标题式的 `Best Configuration` 和句式的 `Select the best configuration.` 都可以，不能在同类标签中混用。

保留 OpenROAD、ReAct、QoR、Tcl、PDK、SDC 等正式拼写，代码、变量、单位和扩展名按领域规范。例如变量 k 不强行改 K，ps 不改 Ps。连字符、斜杠、缩写和换行规则需统一。

最终字体验证使用 PDF 字体清单与可编辑源样式。截图能用于观察大小、间距和密度，无法可靠证明具体字体名、字号 pt 数或对象拆分方式。

## 4. 紧凑、舒适与对齐

### 4.1 由内容推导容器

先确定出版尺寸、正文样式、合理宽度与语义换行，量出完整字块，再分配容器高度和边距。可用以下关系理解尺寸，而非按显示行逐个填坐标：

```text
单段高度 ≈ 首行实际字形高度 + (行数 - 1) × 行基线距
容器所需高度 ≥ 全部段落实测高度 + 段间距 + 上下内边距
容器所需宽度 ≥ 最宽一行实测宽度 + 左右内边距
```

优先使用渲染器的文字测量，公式只提供估算。文本框的几何中心不一定是可见字形中心，应在最终渲染里检查视觉居中，不能给每行另加补丁偏移。

### 4.2 有层级的留白

相关词句在一个字块内相邻，同一组件内的步骤次之，不同职责区域之间留出清楚边界或通道。层次由整体分组表达；不设全图唯一间隙，也不规定所有图都采用同一留白百分比。

先解决局部过挤与局部过空，再压缩整图：空的例子区、巨大的图标区、过长的反馈通道可以收紧；字框内边距和箭头入口的必要空间不能一并清除。标题/图标不应占去机制解释所需的面积。

如果例子或引用暂时留空，先判断是否确实还有待填内容：未完成图保留明确状态，不编造填充；最终没有对应内容则收紧区域，而非为统一卡片高度留下大片空白。

### 4.3 对齐与密度

- 同类栏目对齐标题带、正文起点或比较行；不同构造内部可以有不同结构。
- 同一流程行的单行/多行步骤采用一致的容器和中心/基线策略，不逐个凭感觉调位置。
- 长文字优先语义换行或调宽；为几行文字保留独立适当高度，避免每框都套同一高宽比。
- 小标题与说明的距离、同类白框内的上下边距保持一致，比较的是对应关系，而非整个页面所有距离。
- 连线标签占用自己的通道，不与正文共抢狭缝；竖排标签和长裸露标签仅在实际可读且必要时采用。
- 左右/上下块的密度明显失衡时，先调配空间和组织内容；不通过放大简单模块或缩小复杂模块字体来凑齐。

## 5. 源文件与最终渲染验收

需要编辑或交付原生文件时，抽查当前修改涉及的代表性多行段：是不是一个语义文本对象，段落/软换行、行距、段距、tracking、字体和字号是否正确。同框各行没有独立漂移；需要富文本的样式范围没有溢出到正文。

再在最终出版尺寸查看输出，检查断词、贴边、溢出、局部缩字、过密和过空；同时放大检查字形和基线。源结构正确与最终外观舒服必须同时满足，任一方不能替代另一方。

这里只补具体制作与核验规则，不要求为每次改字创建新的排版引擎、自动修复脚本或逐词测试。
