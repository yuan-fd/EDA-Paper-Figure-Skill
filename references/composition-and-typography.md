## 1. 图的任务与主构图

开画前完成一句话：这张图帮助读者回答什么问题，需要读懂什么对象和关系？运行方法可能解释“谁依据什么采取动作、结果如何验证”；罗列图可能只需说明组成，比较图可能需说明差异，不能一律要求因果闭环。

### 1.1 共性：可共享的阅读规则

对象与关系准确，内容有归属，同级文字样式一致，主次有依据，标签就近，最终尺寸可读。这些可以跨图复用；Agent 白框、执行底座圆柱、三个背景层则不能作为跨类型通则。

### 1.2 异性：由图的任务决定结构

| 类型 | 首要问题及组织依据 | 线与箭头表达 | 重点与验收 |
| --- | --- | --- | --- |
| 架构图 | 谁负责什么、属于哪里、共享什么；按职责与范围组织 | 请求、数据、依赖、反馈，不默认表示时间先后 | 对象类型与归属清楚，不把所有组件平铺同级 |
| 流程图 | 如何依次运行、在何处选择/迭代/停止；按过程组织 | 顺序、条件、循环；标清真正分支条件 | 一轮能沿线读完，失败/通过/退出不含糊；不把能力清单串成步骤 |
| 原理图 | 为什么会发生变化、局部机制如何实现；突出实体关系和变换 | 电路连线、逻辑/因果关系、变换；普通连线不都带箭头 | 保持领域符号、同一负载/输入与真实因果，不用框图掩盖关键拓扑 |
| 罗列图 | 有哪些成分/能力/类别，如何归组；按分类依据组织 | 通常无顺序箭头；可用分组、括线、包含关系 | 成员与分类维度清楚，不强造流水线或闭环；完整性以图的范围为准 |
| 讲解图 | 读者理解难点是什么；按概念—示例—局部放大或对应说明组织 | 引线、映射、放大关联、演示变换，不都表示执行 | 注释有明确锚点，主图与解释不同级，读者无需自行猜测对应关系 |
| 对比图 | 在什么共同维度下有何差异；按对齐比较项组织 | 采用各自真实内部关系；列间不随意加演进箭头 | 共用指标/条件/抽象层次，缺失项明确，不强行等面积也不使一方因缩字被弱化 |
| 时间轴/演进图 | 哪些事件在何时发生、是否存在演进；按时间组织 | 轴向表示时间，不自动代表因果或技术替代 | 标清时间范围；不按比例需明确；等距节点不能暗示等时间跨度 |
| 结果图 | 数据支持什么结论；按度量、基线、不确定性组织 | 由数据图语法决定 | 不以装饰色或无标尺的面积暗示未给出的提升 |

类别是阅读任务而非互斥标签。同一图可有主任务与局部辅任务，例如分类比较配时间轴、系统交互配 Clone 原理示意。对每个区域选择恰当语法，再用字体、颜色和标注方式保持系列一致，不能让整图被一个架构模板支配。

### 1.3 不能机械迁移的规则

- 架构图按职责划分的背景层，不必搬进时间轴或罗列图。
- 罗列成员不必画箭头；流程步骤有真实先后时才画顺序箭头。
- 正交连接是模块通信和流程的默认；电路原理使用真实线网，必要的局部回路或讲解引线可以采用无歧义的曲线，不将所有图形强制直角化。
- 对比图的栏目标题和比较维度宜对齐；各栏内部机制可以不同宽度、步骤数和结构。不要在同级公平比较与无意义等面积之间混淆。
- 时间轴节点与电路连接点有实际符号含义，不能因本系列避免装饰圆点而全部删除。
- 讲解图可以采用清楚的引线文字而不逐条套框；较长说明仍应在明确的注释范围内组织。

这些是组织依据，不是固定模板。双栏、主图加局部放大、交互闭环、时间轴都可采用，只要适合当前关系。

参考论文先借鉴信息组织：如何分组、如何让主体突出、如何区分对象。用户说可以参照或照抄风格，也不自动授权搬用它的科学内容或再发布其素材。原图结构有问题时先重组对象与关系；不能只换颜色、字体和边框。

## 2. 层级、权重与空间

区分三个不同问题：

- **归属**：浅背景板或外框说明哪些对象属于一个系统/职责范围。
- **对象类型**：Agent、工具、内容、数据使用能分辨的符号与标题方式。
- **主次**：核心机制获得合适位置、面积与局部强调；输入、工具和示例提供支撑。

浅背景板不能代替内容框；同样，给每段话加框也不能自动产生系统层级。

面积按有效内容、关系复杂度和阅读路径分配。Single Agent 的机制较简单，就应比复杂协作结构窄；支持诊断 Agent 可以独立归属，但不必比执行主体更大或更艳。同级步骤保持相同的字体、边框和基本内边距；非同级模块不必等宽等高。

先确定主机制和关键连线，再排辅助输入、工具与例子。总纲/总分类可用深底白字；详细说明用白色内容区。标题不能比研究机制占更大视觉重量。通过位置和结构形成主次，不用任意放大字体或随机添颜色制造重点。

“去均匀感”指取消无意义的等面积、等内容量、等强调，不是故意破坏必要的对齐、等距与对称。

相关区域可共享连续背景板，减少无效缝隙；不同职责仍用标题、边界或分隔线辨认。不能为了连成一片而合并不同对象的语义。

## 3. 内容压缩与机制解释

### 3.1 信息取舍

先列出原图里影响读者理解的概念与关系，并标明修改后去向。结构大改时至少在内部完成这份对应，避免“美化”后核心信息消失。

| 内容级别 | 处理原则 |
| --- | --- |
| 核心 | 问题/目标、独特机制、关键关系与决策条件、验证和输出依据应可辨 |
| 支撑 | 与理解有关的输入、指标、共享资源可归组、缩写或迁入清楚的内容框 |
| 可省 | 无信息图标、重复标题、正文已充分解释且与本图无关的细节、用户明确删除项 |

压缩顺序：删除重复表达 → 归并同类内容 → 重新换行与组织 → 调整相邻模块占比和连线路径 → 收紧有效间距与画布。字号改变放在后面，不能把所有内容缩到读不清。

用户明确授权简化时，可概括实现细节；概括必须保持能区分该方法的机制。没有硬性信息保留百分比，不能把“保留所有文字”与“删掉大部分机制”当作唯二选择。

### 3.2 从“能做什么”推进到“怎么工作”

对于描述可执行或迭代优化方法的流程图，使以下链条可读：输入证据 → 诊断/决策依据 → 动作或产物 → 执行/测量 → 如何进入下一轮或决定输出。确实没有迭代的方法不添加反馈线。原理图可只解释关键变换，罗列图可只说明组成，不把这条链当成所有图的强制结构。

“Analyze → Optimize → Evaluate”只列泛词，通常解释不了具体机制。Timing ECO 的例子可以展示 cell/wire/fanout 诊断、候选修复的预期收益与旁路风险、目标化 Tcl 批次及 OpenROAD 测量反馈。具体内容必须核对当前来源。

不要把能力清单画成必经顺序：Sizing、Buffer、Clone 是可用动作，不表示每轮三者串行执行。Example Stages 是作用位置，Example Roles 是角色；用阶段链和虚线作用标记等明确关联，不能画成同类列表。

### 3.3 用图替代文字的边界

有空间或拓扑含义的信息优先尝试小示意：负载分摊、路径共享、候选筛选、阶段适用位置。抽象的风险比较、约束、返回指标仍可用短文字框。

示意必须保留可比输入、同一逻辑功能与必要对象。Clone 的示意中，复制前后是相同负载集合，由同功能门分担；不编造 ps、WNS 提升或必然改善的结论。标明 Example / Illustrative，且局部示例不压过主体，也不冒充完整算法。

## 4. 文字归属与框的层次

| 文字用途 | 放置规则 |
| --- | --- |
| 多行说明、能力清单、输入成分 | 放进其所属的白色或浅色内容框，保持清楚内边距 |
| 模块名、层名、总纲 | 放在所属外框或背景板的标题位置，可用深底白字或有色标题 |
| 动作步骤 | 放在步骤框中，动词与对象明确 |
| 关系标签 | 就近放在线旁，无需套框，不压线、不落在分叉点上 |
| 短指标或局部引线标签 | 归属明显时可无框，避免变成长说明 |
| 图例、示例说明 | 仅在确有必要时出现，归入自己的小范围 |

“文字尽量不裸露”是归属与阅读组织要求，不是每个词都画一个胶囊。已在内容框内的句子无需再层层嵌套；括号、斜杠、换行本身也不能替代对象关系。

背景和文字框不能糊在一起：外层退后，内容区通过白色/更浅底色、细边界和留白显现。检查实际印刷大小，不只比较放大后的色值。不能靠加粗所有框线或套阴影掩盖层次问题。

长说明尽量左对齐；短步骤名、紧凑字段组可居中。同一类型采用同一对齐策略，按短语和语义换行，不把完整名词拆得支离破碎。不要为了塞进旧框，给个别段落自动缩小字号。

同一内容段的多行必须共享文本对象、宽度和排版属性，不使用独立文本框逐行凑 y 坐标。标题与正文的富文本、行距/段距、基线和容器计算见 [文本对象与空间排版](text-layout.md)。

## 5. 色调、背景与图标

本系列以深蓝/深灰提供稳定的标题和文字，浅蓝/浅灰作为范围背景，白色内容区承载细节，少量暗红作角色身份或局部强调。“暗色调”不等于整张深黑底，也不等于给每层分配一种鲜艳颜色。

- 正文默认深色；Agent 红标题、内容蓝边和证据蓝线延续已确认系列语法。
- 色值起点在设计经验第 2 节；绿色等中途方案不作为当前系列默认，当前明确指定的灰色应优先。
- 形状与边界先说明对象，色彩辅助区分。不同对象不能仅靠难以分辨的浅色变化判断。
- 全图保持统一色义；局部示意如果用红标出 High Fanout 等问题对象，标签与独立范围必须说明局部含义，不暗示红线在全图统一表示错误或反馈。
- 同类动作用同等视觉待遇。Clone 不能无依据单独换底色，暗示它优先于 sizing/buffering。
- 实线/虚线也属于语义编码：可分别表示实际传递和作用范围、周期/条件关系，但同图不可一条虚线当应用范围，另一条无解释地当数据流。
- 灰度下仍应依靠标题、边界、线型、布局看懂关系；不能只靠红绿识别。

图标需要提供类型或机制信息。小机器人可标识 Agent；文件折角可标识上下文文档；圆柱可标识持久状态。复制多个机器人、灯泡、扳手、Task/Checkpoint 图标不会增加过程解释。

论文使用适量图标帮助识别对象，图标从 [Flaticon](https://www.flaticon.com/) 检索，不自行创造。优先选择同一套或风格一致的线性矢量素材，统一视觉尺寸、笔画和配色，安排在确有识别价值的位置，不给每个步骤配装饰。PPT 中转换为可编辑原生形状/路径；来源记录、转换与验收见 [图标来源与 PPT 可编辑交付](icons-and-editability.md)。模块框、箭头、圆柱和电路逻辑符号仍按对象语义绘制。

## 6. 字体、字号与命名

### 6.1 字体

制作时将字体、字号、行距、段距和内边距统一管理为当前图的少量样式，局部调用按语义引用；已有样式或原生主题够用就复用，不为此另建主题系统。具体对象规则见 [文本对象与空间排版](text-layout.md)。

本论文默认 **Times New Roman**。不要用 Times、Nimbus Roman 或通用 serif 的实际替换却声称已经使用 Times New Roman。检查最终 PDF 的嵌入字体，同时核对粗体、斜体、数学符号、上下标；矢量图中不能一半正文 Times、一半公式意外换成另一套字体。

SVG 的可编辑文字通常依赖查看环境已安装字体；需要外观固定的投稿版本优先提供嵌入字体的矢量 PDF。不得将 PDF 转曲或图片化后再声称其中的文字仍可编辑/可搜索。

### 6.2 字号

按最终插入论文的物理宽度选字号，而不是按屏幕预览或大尺寸 PPT 页判断。一般仅用少数层级：模块标题、主要内容、必要注释。层级可同时借助粗细和位置体现，不要求标题一定比正文大很多。

历史单栏实例宽 89 mm：A2-ORFO v3 标题 7.0 pt、内容 6.7 pt；TimingECOAgent v5 过程稿 7.0 / 6.5 pt。这是紧凑版面的实例，不是新的投稿规范或普适下限。新图先在目标宽度尝试舒适字号，放不下先改结构；投稿要求优先。

最早双栏架构图出现过 5.3 pt 的最小文字，仅记录事实，不能反向成为所有图可接受的字号阈值。连续注释明显小于正文、同级字号不一致、局部自动缩小都要核查原因。

线宽、箭头头部、边距也按出版尺寸核验。可从现有单栏图约 0.5 pt 的连线起步，查看印刷效果后调整，不能只改字不改几何。

### 6.3 大小写与符号

本系列图内短标签默认 Title Case，冠词、短介词、连接词依所选规范小写；完整解释句采用 Sentence case。图注遵循期刊体例，不机械改成标题式。

保留正式名称、缩写、代码与文件扩展名的拼写：OpenROAD、TimingECOAgent、ReAct、QoR、PDK、SDC、SPEF、STA、Tcl 等，不能把它们机械 title() 化。建立本图术语表，同一词只用一种写法。

例如 `Design / PDK / Config / SDC`、`Goal / Constraints` 应在同一类别规则下统一；代码标识或原命令参数不随图内标题规则改写。斜杠、连字符、缩写、标点与换行处理在同图一致。不以 `·` / `•` 装饰列表。

## 7. 系列统一与版面尺寸

### 7.1 统一与变化的边界

| 应统一 | 随内容变化 |
| --- | --- |
| 字体、同级字号与命名规则 | 图的阅读路径和长宽比例 |
| Agent/工具/数据的视觉语法 | 主体位置与各模块面积 |
| 蓝灰红色系、边框与箭头规格 | 分层、交互闭环、时间轴或局部变换 |
| 内容归属、标题和标注方式 | 是否需要示例、哪些机制占更多空间 |

两图并排看，如果不同方法只表现为相同模板里的文字替换，就要重新选择主构图。A2-ORFO 可突出控制与阶段感知执行；Timing ECO 可突出上下文、决策、工具测量和状态的交互。依据实际机制区分，不能为差异而随意换颜色或添加装饰。

### 7.2 单栏压缩

先确认论文真实栏宽、允许图高和放置方式。ACM 单栏约 89 mm 仅为本项目实例；以实际文档为准，单栏不等于正方形。

将宽图改成单栏时重排结构和阅读顺序，而非整体缩小一半。让简单模块少占宽度、把同一标题中的次要词放第二行、合并冗余间隙；连线通道和文字内边距属于有效空间，不能一并压没。

减少纵向空白时联动背景范围、回路线和画布，避免留下已删除页脚的空间。保留必要分组与呼吸空间；不能为了“长宽接近”牺牲阶段顺序、可读性和对象边界。
