# 审查与验收

新图先审内容与结构，再审外观与文件。局部改图检查变化及受其影响的相邻区域，不每轮强制重做所有检查。这里的检查不等于另建一套绘图或测试框架。

## 1. 内容与来源

- 能指出关键对象和机制在论文正文、图注或代码中的依据。
- 参考风格与科学内容分开；找不到独立论文或原图时如实说明搜索范围和结果，不借相似论文顶替。
- 模型预测、工具测量、示意例子、实验结果表达不同。没有数据不写精确收益，没有来源不编模块或项目名。
- 常规迭代、周期校准、条件分支、最终选择的触发关系正确，不把可用动作清单画成必经顺序。
- 重构前后核对关键概念的去向；核心机制、约束与验证依据没有因美化消失。用户明确删除项按对应图保留删除。

## 2. 对象与构图

- 已判断主图与局部区域的类型；罗列图不强造流程，原理图保留真实拓扑，对比图有共同维度，讲解图的注释有锚点。混合图按区域使用不同关系语法。
- 图能回答本次目标；方法图能看出决策和运行机制，分类图能看出比较依据。
- Agent、操作、工具、阶段、产物、数据和约束不会因外观相同而被误读成同类。
- 主体、支持对象、示例的面积与职责相称；不存在为了均匀而等面积的空卡片。
- 长说明有明确归属，白色内容区与背景板可分辨，标题和线旁短标签没有被机械套框。
- 相邻系列图统一视觉语法，同时按内容形成各自主构图。最新待审稿不标成已确认基线。

## 3. 连线审查

为关键关系核对“源、目标、载荷、方向、线型、触发条件”，按下列顺序判断：

1. 指向和关系正确。
2. 节点锚点、总线、汇合和交叉没有歧义。
3. 实际线段不穿过文字和无关内容框，箭头不覆盖文字或另一箭头。
4. 折点尽量少，通道有可见间隙，目标入口前有清楚箭杆。
5. 同类步骤的等距、分发对齐与约定对称满足实际约束。

等距或对称只检查确实同类、且当前布局需要的部分。正交也是默认选择，不能因此强制把电路、电路波形或统计曲线改成直角折线。

交叉不等于连接。避不开交叉时改变通道或使用清楚的跨越表达；有意连接的总线几何精确相接。本项目不使用装饰圆点，也不靠随意添加圆点掩盖断线。

检查路径的真实线段，而非只看整条多折线路径的包围盒。必要时核查箭头头部实际尺寸、折点和框边的距离，不能通过局部缩小头部来隐藏拥挤。

## 4. 字体、色彩与最终尺寸

- 对修改涉及的多行段核查原生源对象：同一语义段共用一个文本对象；标题/正文差异用富文本或有依据的独立段，不逐行手摆。
- 字符间距、行距、段距、内边距分别有一致规则，无粘贴残留样式、默认段后空白或任意空格撑宽；同类内容的可见基线节奏一致。
- 按真实插图宽度查看最终 PDF，同时放大逐区检查；屏幕放大好看不代表印刷可读。
- PDF 字体清单与可见字形符合约定；公式、下标、特殊字符无意外替换或丢失。
- 同级文字字号和样式一致；术语、Title Case、正式缩写经过人工核对，不能只运行 title()。
- 内容框有足够内边距，文字不溢出其容器，自动缩字没有掩盖排版问题。
- 全图颜色和线型有稳定语义；没有某个同类动作被随机异色突出，灰度下基本结构可辨。
- 图标具有可说明的信息价值，尺寸从属、风格一致，没有重复装饰占位。
- 新图标来自 Flaticon，有可核对的素材来源；PPT 中已转换为原生形状/路径，按图标核对部件编辑能力，不能以插入 PNG / SVG 图片代替。方法见 [图标来源与 PPT 可编辑交付](icons-and-editability.md)。
- 局部密度与留白合理：没有一边大量空白、另一边挤到缩字；没有因等高卡片、空示例区或过长回路浪费版面；必要的字框边距与走线通道仍保留。

截图只能直接支持外观观察。具体字体名、实际 pt 字号和原生文本对象结构需由源文件/最终 PDF 验证，不把推测写成已确认的缺陷。详细方法见 [文本对象与空间排版](text-layout.md)。

## 5. 文件与交付

核对页面尺寸、最终格式和用户指定保存位置。需要可编辑文件时，按 [可编辑制作与核验](editable-delivery.md) 检查原生对象及重渲染；只要求 PDF 时不额外制造不需要的 PPTX / Draw.io。

最小检查组合：

- **结构**：文件能解析/导入，所需字体、文字、形状和关系真实存在。
- **几何**：变化涉及的文字边界、线段、锚点和尺寸约束通过检查。
- **目视**：查看实际最终文件的渲染并与最新基线比较，不能只看生成过程中的 PNG。
- **副本**：用户保存目录的文件与已验证交付文件一致；保留旧版与用户修改。

自动检查能定位溢出、重叠、未嵌入字体、部分几何问题，不能证明科学内容正确或审美成熟。不得为了消除误报而给正常关系标签加框，或删去必要回路。

## 6. 拒绝交付的问题与可接受差异

以下情况需要修正后再交付：错误箭头或科学关系、关键机制被删、不可读文字、实际穿字/断线、错误字体、缺失箭头头部、所承诺可编辑对象不存在、交付了错误版本。

不同职责的宽度不相同、不适用的对称检查、确认无穿字的路径包围盒警告，不能直接判为错误。必要时记录实际核对结论，不编造“全部检查零警告”。

## 7. 迭代与规则沉淀

- 将用户本轮编号对应到实际修改与核验，保留之前尚未完成的要求。
- 判断自然语言描述的意图：移动某框可能是在要求等距和跨列对齐，应联动相关约束，而非只改一个坐标。
- 用户只要求导出、换字体或改局部线条时，不擅自删信息、换构图或加图标。
- 用户明确要求结构重塑时，可以改变布局，但核对信息保留与机制解释。
- 记录“已确认”“可用但需区分风格”“待审”状态；中途撤回的方案不升格为全局禁令或默认模板。
- 新经验分别进入通用规则、项目风格或案例，避免越积越多的相互矛盾绝对命令。

skill 本身修改后，验证入口元数据、相对链接、引用资源和已有几何脚本；这些检查不能替代后续真实绘图中的效果验证。
