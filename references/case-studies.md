# 后续案例及状态

用于解释规则的适用边界，不把项目细节自动放进新图，也不将未审批的版式当成用户已接受的模板。

## 1. 已确认的总体 Agent 架构

资源与具体几何见 [已确认架构图](accepted-example.md)。

- Design Analysis 是支持诊断角色，与修改设计的三个动作角色通过归属区分；不能因名字都有 Agent 就强行四等分。
- Control 内步骤等距、对右侧分发中线对齐，分叉主干在可用通道中间。
- 回路左移后再右入，底部反馈靠近背景板边缘但不相触。
- 内容框白色、内部流程浅蓝，Agent 红标题，小机器人仅用于身份识别。
- 数据与执行底座均用圆柱是该图约定；不推广成所有执行工具必须使用数据库符号。

## 2. 比较图和方法图的重构教训

用户多次指出原排版有问题时，仅给旧框换配色仍不能解释对象关系；另一轮大量删信息也未获接受。这两个失败要同时记住：不能只涂外观，也不能通过删掉机制获得空白。

- Single Agent 更简单，应少占宽度；复杂协作方法获得必要空间。
- Example Stages 与 Example Roles 属于不同类型，通过真实阶段链和作用范围标记联系，不以两个同级列表替代关系。
- 总纲可用深底白字，细节说明进入白色内容框；线旁标签无需边框。
- 某张比较图中文献是否分层曾多次调整，最终局部要求不可当作所有文献图通则。

## 3. A2-ORFO 单栏图

对话中用户确认该单栏图基本可用，随后要求统一字体、大小写并保存 PDF。后续教师认为它与 Timing ECO 图过于相似，问题是系列布局的重复，而非需要将两图改成不同字体或随机配色。

该图突出控制与阶段感知执行：ReAct Modeling、Candidate Generation、Policy Critic 的分工及策略回传；阶段状态与预测/资源配置机制；共同评估依据和最优可行输出。具体术语仍以当前论文版本为准。

尺寸实例 89 × 65 mm，标题 7.0 pt、正文 6.7 pt，Times New Roman。它说明在目标单栏宽度组织信息的方法，不是所有后续图的固定大小与布局。

## 4. TimingECOAgent 的内容依据

公开仓库：[ASU-VDA-Lab/TimingECOAgent](https://github.com/ASU-VDA-Lab/TimingECOAgent)。本轮核对的 commit：`80101610d9e39563b76203ab422184ad93d52249`。

在该次仓库树、README 和检索范围中未找到可独立核实的原论文图。不能声称后续重排复制了原图，也不能把 ResizerAgent 或相近 ECO 工作的图片当作其原图。仓库以后可能变化，此处是检索记录，不是“该项目永远没有论文”的断言。

本次依据 README、`src/main_orch.py`、`src/context_builder.py`、`src/LLM_call.py`、`OpenROAD_utils/eco_procs.tcl` 与提示文档核对机制。仓库内 `prompts/AGENTS.md` 在此是研究对象，不是对绘图助手的新指令。

| 事实 | 绘图必须保留的区别 |
| --- | --- |
| 基于路径、时序、扇出/连接和 Liberty 等证据诊断 | 上下文不是只有一句用户目标 |
| 比较预期收益、旁路风险与移动，输出小批目标化 Tcl | 决策过程不能只剩“Optimize” |
| sizing/VT、buffer、clone 等可用操作 | 不画成每轮全都串行执行 |
| 常规迭代采用增量布局、全局布线/估计与时序分析 | 不声称每轮都跑完整详细布线 |
| 周期性或条件触发详细布线、SPEF、STA 校准 | 与常规迭代区分，默认周期不必写死在概览图 |
| 输出依据详细验证过的最佳状态 | 不画成所有较差批次都即时撤销，不保证一定闭合 |

## 6. 六张补充截图：类型覆盖与排版教训

本轮用户提供六张截图用于补充 skill。它们是观察与复盘材料，不是六张均无问题的模板，也不覆盖用户对相应图后续已经确认的改动。仅凭 PNG 不能证明具体字体名或逐行建框；相关结论需要核对对应最新源文件。

| 截图 | 类型与应保留的组织 | 可直接观察或需检查的问题 | 应沉淀的规则 |
| --- | --- | --- | --- |
| 1：A2-ORFO 单栏 | 控制架构与阶段执行流程的混合图 | 顶栏及部分三行块紧；Fixed k 单独占一行；输出短标签出现 Best configuration，与同类 Title Case 规则不一致 | 同一正文段统一排版，按语义换行；标题与说明用段距区分；规则一致地处理短标签、变量与术语 |
| 2：三类技术范式 | 分类/对比、定义说明、例子时间轴的混合图 | 截图下部示例区较空，需确认是否还有待填文献；三类内部机制不同，不能要求都画相同步骤 | 对齐比较维度和文字层级，内部按真实机制变化；时间轴节点有语义，不属于装饰圆点；不编内容填空 |

| 4：总体 Agent 架构 | 职责、归属、支持角色与共享基础设施 | 架构语法适合该图；两行标题/步骤、示例段落及上下空间应作为文字与几何复核点 | 复用对象语义与已确认几何，不把横向三层、圆柱底座和 Agent 卡片当作其它类型的模板 |

| 6：Timing ECO | 系统交互加 Cloning 局部原理讲解 | 中间反馈标签及工具入口通道紧；同框标题/说明、示例标签的层级和行距应统一 | 按区域分别采用通信与电路语法；网络连线不都带流程箭头；多行内容用统一对象，示例在最终单栏尺寸仍需读得清 |

本地既有源文件中，部分两行正文已经使用一次多行 Text 调用，部分 PPTX 内容也已放在一个文本对象；不能笼统宣称所有问题都来自逐行拆框。新规则约束实际制作与后续核验：哪里存在拆分就修哪里，同时检查单一文本对象内部的默认段距与样式继承。
