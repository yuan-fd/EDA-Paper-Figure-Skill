# 可编辑制作与核验

## 1. 先确认编辑基线

先打开当前源文件；用户若在桌面或别处改过，不能重新生成后覆盖他的修改。文件大小/时间用于筛选，内容比较才用于确定是否相同。对未保存的截图修改，按截图核对，并把能确定的改动带入新版。

以用户最后确认的版本为基线，另存新版本。PNG 是外观参考，原生对象文件是编辑来源；两者不一致时先检查实际修改，不能默默回退。

不要因为用户换了交付格式，就重新设计内容、图层和文字。图到 PPT 是同一幅图的原生对象表达，不是新增一张有封面和装饰的演示文稿。

## 2. 用同一份对象和坐标

多格式交付时优先维护一套场景记录：对象类型、矩形坐标、层级、填色/边框、文字内容/样式、连线顶点与端点。所需预览、SVG/PDF、Draw.io 和 PPTX 从同一套记录或原生源文件转换，避免重复手工排版；不为只要求 PDF 的任务另建完整多格式导出框架。

不强制新建绘图框架。现有原生文件能直接修改就修改；已有脚本和对象记录够用就复用。只有当前图需要的类型才实现导出。

推荐映射：

| 原图内容 | Draw.io | PPTX |
| --- | --- | --- |
| 范围框/步骤/背景 | 原生矩形/圆角矩形 | 原生矩形/圆角矩形 |
| 圆柱 | 原生圆柱，或矩形与椭圆组合 | 原生 cylinder，或原生形状组合 |
| 文字 | text cell | 文本框，保留文字 |
| 直线 | 原生 edge | 原生线/连接器 |
| 正交多折点线 | edge + points | 连接器或可编辑自由路径 |
| 图标 | Flaticon 矢量素材，保留来源与可编辑路径 | Flaticon 矢量转换成原生形状/路径并编组 |

历史样例的小机器人由矩形和线构成，底座没有图标。新图标按 [图标来源与 PPT 可编辑交付](icons-and-editability.md) 从 Flaticon 选取并转换，不再自行拼画身份图标。已确定的模块框、箭头和精确电路图形继续使用原生几何制作。

用户明确要“可编辑”时，不能把整张 PNG 或 SVG 当作一个图片对象嵌入。矢量图片也不自动等于可以逐字、逐框、逐线编辑。

PDF 是投稿与排版交付，SVG 是矢量源格式，PPTX / Draw.io 是对象编辑交付；分别描述真实能力。已存在且可修改的 Matplotlib / SVG / 原生图稿直接复用，精确的科研线框图不必重走生成式图像流程。

PDF 优先保留矢量路径、可搜索文字并嵌入所需字体；PNG 仅作预览。SVG 保留文字时检查字体依赖，转为路径会改变逐字编辑能力。不能把这些格式一概称为完全可编辑。

## 3. Draw.io 的实际注意点

- 如果生成 XML，为节点分配唯一 ID，检查 parent/source/target 指向真实节点。
- 分组采用父节点局部坐标；连线折点与端点也必须使用所属父节点的坐标，不能混用绝对坐标。
- 箭头要保留端点和中间折点，避免软件再次自动路由而绕远路。
- 有意连接节点时保存锚点；自由端点和显式折点则保持实际几何。不要声称每条线都会自动跟随所有移动。
- 顶点和线段精确相交；总线不能因为所属分组不同而出现微小断口。
- 如果输入是压缩的 diagram 数据，要先正确解码，不能把压缩内容当普通 XML 文本替换。

## 4. PPTX 的实际注意点

使用当前可用的 presentation 工具及其 skill 文档，按用户已定的尺寸、字形、色彩和布局制作单页图，不强制改成 16:9。

最早样例在当时环境使用第一方 Artifact Tool；这是制作经验，不要求新环境强行使用已不可用的接口。读取当前可用工具文档，按当下要求完成 authoring 标记、导出、finalize 与验证。运行时目录通过当前依赖定位方式读取，不将某次会话中的缓存版本或用户名写成通用脚本常量。下文 API 细节也要与当前版本核对。

### 坐标与文字

- 同一内容段的多行放入一个原生 text body，以软换行/明确段落与 runs 排版；标题和正文优先在同一对象中表达层次。不能每行一个文本框后仅编组冒充合并，相关说明见 [文本对象与空间排版](text-layout.md)。
- 明确设置行距、段前段后和内边距，核对字符间距与富文本的字体继承；源里一个段落导出成多个 PDF span 并不等于逐行建框。
- 清楚区分几何单位、CSS px、pt 和 EMU。Artifact Tool 的几何与数值 `fontSize` 使用 CSS px；显式 pt 属性按接口文档使用。
- 等比例转换整幅图：位置、形状尺寸、线宽、文字大小一同缩放。
- 文本框去掉不必要的默认内边距，保留合理且一致的边距，保持原来的水平/垂直对齐；检查换行，避免自动缩小掩盖问题。
- 如果源文本边界是精确测量的紧包围盒，必要时加少量安全空间，保持中心/左对齐锚点不变。
- 183 mm 宽图的 5.3 pt 字体不能直接照搬为一个大尺寸 PPT 页面中的 5.3 px；必须按整个画布比例换算。

### 线与箭头

- 直线连接器和自由路径都可原生编辑，但前者可有吸附能力，后者通常通过 Edit Points 修改。不要混淆两者。
- Artifact Tool 连接器的 `head` 是来源端，`tail` 是目标端；源到目标的箭头用目标端装饰，不能反过来。
- 用自由路径保持正交折点时，确认它的箭头头部也进入 PPTX；预览里缺箭头头部就是未完成。
- 如果当前工具不能直接保留路径末端装饰，可做狭窄的 OOXML 修正，但必须保持形状对象和路径，并重新验证。已确认样例是在相应形状的 `a:ln` 中写入目标端 `a:tailEnd type="triangle"`，不是添加一张箭头图片。
- 普通图标线不能误加箭头；对指定的边对象操作，不能给全图所有线批量加 tailEnd。
- 多段线的包围盒可能很大，碰撞检查必须看实际路径，不能把整块包围盒覆盖的文字都当作真实交叉。

### 图标

图标需要完成矢量到原生形状/路径的转换，按每枚图标编组。核对其部件、颜色、笔画和路径编辑能力；嵌入一枚可缩放 SVG 图片不作为原生对象交付。保存 Flaticon 来源与许可信息，转换和验收细节见图标参考。

## 5. 交付前的实证检查

最少检查以下三层，不能互相替代：

1. **文件结构**：能够重新解析/导入；ID、关系、页面尺寸、字体与所需原生对象存在。
2. **几何**：当前用户关注的等距、对称、锚点、边界间隙通过实际数值检查；文字不越出页面或容器。
3. **外观**：打开最终导出的图/渲染，逐个区域与最新基线比较，检查折线、箭头、字、框和留白。

对于 PPTX，解包检查原生 `p:sp` / `p:cxnSp` 和 `a:t`，以及箭头头部。完整原生线框图通常不应含一张替代全图的 `p:pic`。如果当前图本来含合法的显微图、版图截图或外部图像，则保留这些图片，不能为了“没有图片”的检查而删除论文证据。

不要把样例对象数量当成以后所有图的门槛。样例的 188 个对象、77 个文本和 26 个箭头头部仅用于验证那一份导出没有丢失内容。

### 科研绘图 QA 的适用方式

- 使用科研绘图 skill 时，运行其源码、最终 PDF 字号、碰撞检查和适用的对齐检查。
- 架构图只有一个 plotting canvas 时，plot-panel 对齐为不适用；这不豁免 Agent 内部等距和跨模块对齐。
- 关系标签跨两个浅色背景层可能产生 fill-edge WARN。实际看清文字后记录原因，不重新给它套框以消除警告。
- 外围折线的大包围盒覆盖文字可能导致 connector-over-text WARN。沿真实线条复核，而不是删除正常反馈线。
- PDF 字号应按目标版面和投稿要求判断；历史样例最小 5.3 pt 只是个案记录，不是推荐下限。新单栏图使用过约 6.5–7.0 pt 的紧凑配置，也不能自动视为投稿规范。PPT 放大页面的字号不能直接用于声称论文印刷字号达标。
- 通过结构检查或 reimport 不等于已经在 PowerPoint/WPS 里实际检查；只有真实打开过对应应用才这样表述。

## 6. 保存与反馈

把已验证的文件复制到用户指定位置，校验副本与交付文件内容一致。保留旧版，使用清楚的新版本名，不能把未验证的中间文件交付。

最终回复给可用文件和本轮核心变化。用户没有要求时，不附一长串 QA 日志、设计复述、临时脚本或“已达到顶刊标准”的自我评价。PNG 可以作为预览，不能替代用户明确要求的可编辑文件。

## 7. skill 分享的边界

用户要求分享 skill 时，发布内容与本机工作目录分开。入口与参考使用相对路径，工具定位按当前环境发现；不打包个人绝对路径、私人文档、聊天记录或无许可的外部图标。资源许可不明确时先完成文字规则与可分享部分，不为发布而擅自授权。

原生样例和预览是否纳入公开包需核对其内容与再分发权限。依赖实际需要的文档可保留，临时输出、缓存与未审稿不作为默认发布资源。用户审批决定发布范围，不能把更新本地 skill 当作自动授权外部发布。
